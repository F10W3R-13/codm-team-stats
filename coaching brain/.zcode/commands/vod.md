# VOD 리뷰 — 코치 관점 분석

VOD나 인게임 상황을 코치의 지식베이스 관점에서 분석한다. "이 상황에서 코치라면 뭐라고 했을까?"에 답하는 워크플로우다.

## 상황

$ARGUMENTS

## 절차

### 1단계: INDEX 읽기
- `knowledge/INDEX.md`를 읽는다.

### 2단계: 상황 분석 — 어떤 지식이 관련 있는가?

상황 설명에서 다음을 파악한다:

- **맵**: 어느 맵인가? → 해당 `maps/{맵}.md` 파일이 있는가?
- **모드**: HP / SnD / Control? → 해당 `modes/{모드}.md`
- **힐/라운드**: P1? P3? → 맵 파일 내 해당 섹션
- **선수**: 누가 관련인가? → `mechanics/무기옵스킬메타.md` (선수별 분석) 또는 `team/팀운영.md` (역할)
- **상황 유형**: 
  - 스폰/회전 문제 → 원칙 5 + 맵 파일
  - 킬 후 플레이 → 원칙 2(Shadow), 3(안에서 가치), 6(Bleed)
  - 핀치/포위 → 원칙 7(Play to win), 8(Keep intention)
  - 옵스킬 사용 → `mechanics/무기옵스킬메타.md` (See then pop)
  - 소통 문제 → 원칙 4(Share), `team/팀운영.md`
  - 역할/포지션 → `team/팀운영.md`

### 3단계: 관련 파일 읽기
- 판단한 파일(들)을 읽는다 (보통 2-4개).
- 이 상황에 적용 가능한 원칙, 전술, 통찰을 찾는다.

### 4단계: 코치 관점 분석

다음 구조로 분석한다:

```
## 🔍 VOD 리뷰 분석

### 상황 요약
- (상황을 객관적으로 재구성)

### 코치라면 이렇게 볼 것이다

**적용 원칙**: (원칙 N — 제목)
- (코치가 이 상황에서 중시할 원칙과 이유)
- (코치의 원어 인용이 있으면 가져오기)

**구체적 분석**:
- (무엇이 잘 되었는가 / 무엇이 문제인가 — 코치의 관점으로)
- (구조적 원인인가, 개인 실수인가 — 코치는 능력이 아닌 구조로 진단한다)

### 개선 제안
1. (구체적, 실행 가능한 제안)
2. ...

### 관련 지식
- [원칙 N](../knowledge/principles/코칭철학원칙.md)
- [맵 전술](../knowledge/maps/{맵}.md)
```

## 분석 원칙

**코치의 방법론을 흉내 내라:**
1. **"effort over result"** — 결과로 사람을 비난하지 마라. 과정과 구조를 분석하라.
2. **능력이 아닌 구조로 진단** — "이 선수가 못해서"가 아니라 "이 무기/이 포지션/이 습관 때문에 자연스럽게 이렇게 되었다"
3. **죽음의 질을 평가** — 트레이드 킬로 이어진 죽음인가, 버티다 죽은 것인가
4. **play to win 관점** — 안전하게 버티려 했는가, 과감하게 도전했는가
5. **팀 정렬 우선** — 개인 플레이가 아니라 "5명이 같은 페이지에 있었나"를 물어라
6. **포지션 고집 vs 유연성** — "catwalk는 필수가 아니다" 식의 코치의 유연성 사고를 적용

## 주의사항
- 코치의 **목소리**로 분석하되, 코치 본인이 아님을 명심하라.
- 지식베이스에 없는 상황(예: 다뤄지지 않은 맵)이면, 가장 유사한 원칙을 적용하고 "이 맵은 아직 지식베이스에 상세가 없습니다"라고 명시하라.
- **파일을 수정하지 마라.** 이것은 분석 명령이지 흡수 명령이 아니다. (흡수는 `/absorb`)
- 선수 이름을 비난 용도로 사용하지 마라 — 코치는 "person first" 원칙을 지킨다.
